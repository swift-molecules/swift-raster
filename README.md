# swift-raster

Use this package when you need a grid of pixels as a value: a width, a height and one pixel per position, over a pixel type you choose. Start from `Raster<Pixel>`. It stores, crops, samples, resamples, warps and convolves, and it traverses with `map`, `zip` and `reduce`. It ships no pixel type and knows no colour, channel order, transfer function or blend rule: what a pixel means is stated by the type you put in, so an 8-bit display-encoded pixel and a floating-point linear-light pixel are two different instances and cannot be mixed up. Every operation that has to combine pixels takes the combining function from you. To blend one picture over another, pass the blend to `zip`; the arithmetic for that lives in the package that owns the compositing standard, not here.

## Laws

- A raster holds exactly `width × height` pixels, stored row by row: the pixel at (x, y) is `pixels[y × width + x]`. Construction from a pixel list fails with `.count` when the list has another length or the product does not fit a signed word. Rows are packed; there is no stride and no padding, so equality and hashing compare the size and the pixels and nothing else.
- A raster with no columns or no rows is valid and empty. A raster of 5 × 0 is not equal to one of 0 × 5.
- `init(width:height:_:)` asks for the pixels in row order, (0, 0), (1, 0), …, and stops at the first failure. `subscript(x:y:)` and `row(_:)` trap outside the raster.
- `cropped(to:)` is the region's pixels as a raster of the region's size, and fails with `.bounds` unless the region lies inside the raster. An empty region on the far corner lies inside. `replacing(x:y:with:)` puts another raster at a position, changes no other pixel, and fails with `.bounds` unless it fits. Cropping what was just replaced gives the other raster back.
- `map` visits every pixel in row order, keeps the size, may change the pixel type, and stops at the first failure. `zip(_:_:)` combines two rasters of the same size pixel by pixel in row order, and is `nil` when the sizes differ. `reduce` folds the pixels in row order. The function's typed error is the operation's typed error.
- `mean(against:_:)` is the sum of the error you give for each pair of pixels, divided by the number of pixels; it is `nil` for rasters of different sizes and for rasters with no pixels. `psnr(against:peak:squared:)` is ten times the base-ten logarithm of the peak squared over that mean, in decibels, where your function gives a pixel pair's squared error averaged over its channels. No error at all gives +∞, also for two empty rasters, and different sizes give `nil`.
- Pixel (x, y) covers the square from (x, y) up to but not including (x + 1, y + 1), and its centre is (x + ½, y + ½). `sample(at:_:edge:mixing:)` with `.nearest` gives the pixel whose square holds the point. With `.bilinear` it interpolates between the four pixels whose centres surround the point, first along x in each of the two rows, then along y between the results. At a pixel centre both give that pixel, exactly and without calling the interpolation; along a row or a column of centres only one interpolation is made.
- The interpolation you pass is `(from, to, parameter) -> Pixel`, with the parameter in 0…1: the pixel that is `parameter` of the way from the first to the second. It is the only thing the filtering operations ever ask of a pixel. For nearest sampling it is never called.
- `Raster.Edge` says which pixel stands at a position outside the raster. `.extend` is the nearest pixel inside. `.wrap` repeats the raster, so position p is p modulo the width. `.mirror` reflects it about each border with the border pixel repeated, so the positions beyond `a b c` read `c b a a b c c b a`. `.constant(pixel)` is that pixel everywhere outside. Rows follow the same rule as columns.
- Sampling an empty raster traps, except with `.constant`, which answers the constant. A sample position must be finite; beyond ±2⁶² it is clamped.
- `warped(width:height:_:edge:mixing:from:)` makes a raster of the given size whose pixel at each destination centre is the sample at the source point the function returns for it. The map therefore runs from destination to source, which is the direction a resampler needs. `warped(by:width:height:_:edge:mixing:)` is the same for an affine map given as `Matrix<2, 3, Scalar>`, applied to (x, y, 1). The raster never inverts a matrix: to move a picture by a transform, pass that transform's inverse. The identity map returns the raster under both samplings, a translation by whole pixels moves pixels exactly, and a map onto a window of the raster equals `cropped(to:)`.
- `resampled(width:height:_:mixing:)` changes the size, first along the rows and then along the columns. Each new pixel is an average of old ones with non-negative weights that are normalised over the pixels that exist, so nothing outside the raster is ever read and no edge is needed. `.nearest` takes the old pixel under the new pixel's centre. `.box` weighs each old pixel by how much of the new pixel's footprint it covers: shrinking by a whole factor gives each block's mean, enlarging by a whole factor repeats pixels. `.triangle` weighs by distance from the new centre, reaching one old pixel when enlarging and one new pixel when shrinking: enlarging equals bilinear sampling with `.extend`. Resampling to the same size returns the raster under every filter, and resampling to no columns or no rows gives an empty raster. Resampling an empty raster to a size that has pixels traps.
- A `Raster.Kernel` is an odd number of weights, none negative, with the middle one at the pixel itself. Construction divides them by their sum, and fails with `.empty`, `.even`, `.weight` (a negative or non-finite weight) or `.zero` (nothing to normalise). `Raster.Kernel.box(radius:)` has `2 × radius + 1` equal weights. `Raster.Kernel.gaussian(deviation:radius:)` samples exp(−d²/2σ²) at whole distances out to the radius, by default three deviations rounded up; a deviation of zero is `identity`, and a negative or non-finite one fails with `.weight`. Its weights come from the scalar's own `exp`, so they are as repeatable across platforms as that function is.
- `convolved(horizontal:vertical:edge:mixing:)` replaces each pixel by the kernel-weighted average of its row neighbours, then does the same down the columns of the result. A weight at distance d from the kernel's middle multiplies the pixel d positions further along. A kernel of signed weights that do not sum to one is not offered: its result is a difference of pixels, not a pixel.
- Every average here, in sampling, resampling and convolution, is computed as a chain of interpolations: it starts from the first pixel with a non-zero weight and mixes in each next one at its weight divided by the weight so far. Two consequences hold for any interpolation that returns its first argument when both arguments are equal and stays between its arguments: a constant raster stays exactly constant, and no result leaves the range of the pixels averaged. With `identity` on both axes no interpolation is called and the raster is returned as it is.
- Convolving across and then down gives the same result as down and then across, up to rounding. With `.wrap`, a convolution keeps the mean of the pixels up to rounding.
- Away from the borders a convolution reads pixels directly, so its cost is one interpolation per kernel weight per pixel per axis. A full-HD raster of four `Float` channels under a 31-weight Gaussian on both axes took 0.45 s in a release build on one x86-64 core.
